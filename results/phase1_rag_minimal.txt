Q: How does the ledger recover when Postgres crashes during transfers?

A: The transfer is one transaction, and nothing commits until the last line. If Postgres dies before COMMIT, it discards the whole transaction on restart (WAL recovery), *including the idempotency-key claim*, so there is never a half-transfer. The API returns 503 (`OperationalError` handler). The client retries with the same key, and once Postgres is back, `pool_pre_ping` reconnects and the retry runs as a first attempt. If Postgres died after COMMIT but before the response reached the client, the retry finds the key and replays the stored response. [2]
